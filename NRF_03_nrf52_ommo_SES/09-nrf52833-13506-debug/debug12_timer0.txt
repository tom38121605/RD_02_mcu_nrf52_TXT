

TIMER0 的三个主要功能

   捕获 RX 完成时间	CC0	记录上一次 UARTE 接收完成的时刻，作为后续调度的基准   拍照

   调度 RX/TX 切换	CC1	在精确的时间点触发 PPI，自动启动 UARTE 接收或发送     300us 等rxtx /  3530us + 235us 等接收下一个时间戳包

   接收超时检测	CC2	如果没在规定时间内收到数据，触发超时中断，重新握手            540us等时间戳/ 4040us等握手包/ 3530us + 540us 从新接收时间戳包



主流程：

[UARTE 接收完成]
    ↓
TIMER0 CC0 自动捕获当前值（rxend_time）
    ↓
根据 rxend_time 计算下一次动作的时间：
    ├─ 300us 后发送数据 → 设置 CC1
    ├─ 540us 内没收完 → 设置 CC2（超时）
    └─ 3.5ms 后收下一个 timestamp（timer3） → 设置 CC1       //或是timer0的 CC1   （待验证）
    ↓
TIMER0 计数到 CC1 → 触发 PPI → 自动启动 UARTE RX/TX
TIMER0 计数到 CC2 → 触发中断 → 超时处理



疑问1：为什么 timer0 CC1 接收下一个时间戳包时间窗口是 3530us + 235us
答：   从“上一个包结束”到“下一个时间戳包开始”，中间要经过：数据包延迟（300us）+ 数据包传输时间（323字节，3.23ms）+ 安全余量（235us）

=======================================timer0 中断响应（只响应 cc2超时中断）====================================================

cc0  -- 拍照用，没开中断
cc1  -- rxend和ppi触发，没看中断
cc2  -- 开了中断
cc3  -- 未使用
cc4  -- 未使用

RXTO 事件
    ↓
[中断处理] on_comms_uarte_event()
    ├─ 检测到 ENDRX → 处理接收完成
    └─ 检测到 RXTO → 处理超时

irq_handler(    *p_reg,   *p_cb,   channel_count)

   
    //依次看timer0 cc0 -- cc4的事件标记和中断使能
    for (i = 0; i < channel_count; ++i)
    
        nrf_timer_event_t event = nrf_timer_compare_event_get(i);     //事件标记

        nrf_timer_int_mask_t int_mask = nrf_timer_compare_int_get(i);  //中断使能

        //如果既有事件标记，又有中断使能，在先清除事件标记，再进入中断服务程序
        if (nrf_timer_event_check(p_reg, event) &&  nrf_timer_int_enable_check(p_reg, int_mask))
        
            nrf_timer_event_clear(p_reg, event);    //清除事件标记

comms_uarte_siu_1wire::on_timer_event( event_type)
 

    //如果是timer0 cc2超时中断，则如下处理
    if (event_type == TIMER_EVENT_RX_TIMEOUT)

        if (state != STATE_ERROR)
         
            state = STATE_RX_TIMEOUT;

            //uarte_resource->rx_abort();  // triggers a RX_DONE event，中止uart接收
            //  nrfx_uarte_rx_abort(uarte_instance);
                  nrf_uarte_shorts_disable(p_instance->p_reg, NRF_UARTE_SHORT_ENDRX_STARTRX);   //关闭快照     
                  nrf_uarte_task_trigger(p_instance->p_reg, NRF_UARTE_TASK_STOPRX);             //中止接收
