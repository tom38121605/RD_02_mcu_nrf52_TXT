0. 关于 event task的讲解：
   pending  --  51单片机的flag
   process  --  51单片机的回调函数
   注册     --  函数指针赋值

1. 正确的 pending 实现：

   bool my_pending(void *ctx) 
      return work_ready;   // 只读，不改状态

   ---

   void my_process(void *ctx) 
       if (work_ready)    
           work_ready = false;   // ★ 在 process 里清标志，不在 pending 里清 ★
           // 干活...


2. main_loop_only = true 的理解  (即 in_main )


        AAA= main_loop_only_flags[i];   // 这个任务是否只能在主循环执行   //false 是在所有地方都能跑,含主循环和其它嵌套(死循环)  
        BBB = in_main;                  // 现在是不是在主循环里   
        if( AAA && !BBB) continue;      // 如果任务贴了“仅限主循环”标签（AAA为true），且当前不是主循环（BBB为false）
 
        嵌套：  其实就是主循环之外的死循环

        void event_queue_manager::execute_once() { execute_once_impl(false); }
        execute_once，in_main = false，就是强行扫一圈任务列表，自动筛掉那些只能在主循环跑的任务（AAA=true），让AAA=false只允许在嵌套里跑的任务跑一次
        

        。主循环和死循环其实都不是主要逻辑，主要逻辑是下面
             execute_once()                     // execute_once_impl(false);            //遍历一次 AAA=false的任务
             execute_once_as_main()             // execute_once_impl(true);             //遍历一次 所有的的任务

        。任务1：（比如 USB 状态切换）：标记了 AAA = true。在 main() 的大循环（BBB = true）里会跑；
               但在 flush_tx_buffers 里调用的 execute_once()（BBB = false）里会被跳过，因为此时是在处理 USB 发送，不能中途切状态

        。任务2：（比如后台心跳）：标记为 AAA = false。无论在 while(true) 还是 execute_once() 里都会正常执行


---------

execute_once()	                遍历一次，pending 为 true 的任务执行一次
execute_forever()	        死循环，不断执行 execute_once()
execute_once_with_sleep()	执行一轮，没活就睡觉（__WFI）
execute_forever_with_sleep()	死循环，每轮干完活检查一次，没活就睡觉



execute_once()                     // execute_once_impl(false);            //遍历一次 AAA=false的任务
execute_once_as_main()             // execute_once_impl(true);             //遍历一次 所有的的任务
execute_once_with_sleep()          // execute_once_with_sleep_impl(false); //遍历一次，空闲时进入休眠 
execute_once_with_sleep_as_main()  // execute_once_with_sleep_impl(true);  //遍历一次，空闲时进入休眠  (仅在main中 运行，不能在中断中运行)
