4.  问题： 提示不能强制转换为 uint32   （nrf52840）
       converting a packed 'device_info_len_t' pointer (alignment 1) to a 'const uint32_t' {aka 'const long unsigned int'} 
       pointer (alignment 4) may result in an unaligned pointer value [-Werror=address-of-packed-member]

    分析： 相关代码如下
         typedef __PACKED_STRUCT // 16 bytes total
         {
             uint16_t perm_len;       /* Device info permanent length */
             uint16_t man_len;        /* Device info manufacturer length */
             uint16_t user_len;       /* Device info user length */
             uint8_t  future_use[10]; /* Reserved for future use */
         } device_info_len_t;

         device_info_len_t empty_device_info __attribute__((aligned(4)));
         memset(&empty_device_info, 0x00, sizeof(device_info_len_t));
         nrf_nvmc_write_words(active_page_addr + sizeof(magic_data_t), (const uint32_t*)&empty_device_info, sizeof(device_info_len_t) >> 2);   //错误提示行

    解决： 在代码的前后加 #pragma，屏蔽编译错误 （意思是这里不需要编译器检查错误）

         #pragma GCC diagnostic push
         #pragma GCC diagnostic ignored "-Waddress-of-packed-member"

                 // write device info len 0
                 device_info_len_t empty_device_info __attribute__((aligned(4)));
                 memset(&empty_device_info, 0x00, sizeof(device_info_len_t));
                 nrf_nvmc_write_words(active_page_addr + sizeof(magic_data_t), (const uint32_t*)&empty_device_info, sizeof(device_info_len_t) >> 2);

         #pragma GCC diagnostic pop


5. 提示 unknown option after '#pragma GCC diagnostic' kind [-Werror=pragmas]

    分析：#pragma GCC diagnostic ignored "-Wanalyzer-infinite-loop"

            #pragma diagnostic ignored "-Wanalyzer-infinite-loop"

6：NRF_TIMER_TASK_CAPTURE0 和 NRF_TIMER_EVENT_COMPARE0   区别

答： NRF_TIMER_TASK_CAPTURE0	“拍照”   -- 立刻把当前 COUNTER 快照复制到 CC[0]               //easy，外部 → Timer（存数）            
       NRF_TIMER_EVENT_COMPARE0	“闹铃响” -- 当 COUNTER == CC[0]，硬件自动产生 COMPARE0 事件   //easy，Timer → 向外发出信号

      拍照确实会改变门槛值，因为本来就是要重新设置门槛值 （如当前拍照值 + 1000），所有临时改变没有关系

8.  问：为什么timer3的中断程序中有，而在timer0的中断程序中没有进入/退出临界区的宏

       NRFX_CRITICAL_SECTION_ENTER();   //关闭全局中断（__disable_irq()）
       NRFX_CRITICAL_SECTION_EXIT();     //恢复关闭前状态

   答：TIMER3 中断需要保护多步操作的共享变量，TIMER0 中断只是单步设置状态标志，不会被打断导致数据错乱，所以不需要临界区

          对比项	          TIMER3 中断                                                                     TIMER0 中断
          共享变量                sample_event_trigger_value、synch_event_trigger_value        state
          操作复杂度            多步操作（读 → 计算 → 写）                                                单步赋值
          是否需要临界区      需要                                                                                  不需要


9.  OMMO_APP_ERROR_CHECK讲解:

 
      NRF_SUCCESS          -- 0
      NRF_ERROR_INTERNAL   -- 3

    ---------------------------

      示例1：    

      OMMO_APP_ERROR_CHECK(in_comms_transport_rx ? NRF_ERROR_INTERNAL : NRF_SUCCESS, STRING("unexpected synchronous"), 0);


      拆解如下：

      AAA = in_comms_transport_rx ? NRF_ERROR_INTERNAL : NRF_SUCCESS;
      BBB = STRING("unexpected synchronous")


      if (AAA)  //NRF_ERROR_INTERNAL
       
          // 如果标志为 true，说明发生了意外的同步调用
          OMMO_APP_ERROR_CHECK( AAA,  BBB, 0);
              ommo_app_error_fault_handler(..., BBB, ...); 


      -----------------------


      #define OMMO_APP_ERROR_CHECK(ERR_CODE, STRING, LINE) 
          do { 
              if ((ERR_CODE) != NRF_SUCCESS)   
                  ommo_app_error_fault_handler(..., ERR_CODE, ...); 
                
          } while (0)
          
   ------------------


          
          [调用] OMMO_APP_ERROR_CHECK(err_code, "错误信息", 0)
          ↓
      [宏展开]
          ↓
      do {
          const uint32_t LOCAL_ERR_CODE = err_code;
          if (LOCAL_ERR_CODE != NRF_SUCCESS) {
              ommo_app_error_handler(err_code, __LINE__, __FILE__, "错误信息", 0);
          }
      } while (0)
          ↓
      [如果 err_code != NRF_SUCCESS]
          ↓
      ommo_app_error_handler() 执行：
          1. 关闭中断（__disable_irq()）
          2. 组装错误日志（错误码、文件名、行号、时间戳、附加变量）
          3. COBS 编码
          4. 写入 Flash（保存崩溃报告）
          5. 调用 ommo_app_error_fault_handler()
          ↓
      ommo_app_error_fault_handler()：
          1. 打印错误日志
          2. 触发断点（NRF_BREAKPOINT_COND）
          3. 调用 app_error_save_and_stop() → 系统停止/复位


10.  register_task注册任务队列的讲解

      1）。 程序示例
       //把队列one_hundred_ms_event_pending作为一个子函数，加入到主队列中
       //main_event_queue.register_task(one_hundred_ms_event_pending, one_hundred_ms_event_process);
       //  register_task_impl( nullptr, one_hundred_ms_event_pending,  one_hundred_ms_event_process,  nullptr,  nullptr,  false);

           process_functions[i]    = one_hundred_ms_event_process;
           pending_functions[i]    = one_hundred_ms_event_pending;
           main_loop_only_flags[i] = false;                         //在主循环外也可运行


      2）。 讲解：

        2-0. 关于 event task的讲解：
               pending  --  51单片机的flag
               process  --  51单片机的回调函数
               注册     --  函数指针赋值
               main_event_queue.execute_forever()     --  相当于在while中不断检查flag，如果是1则运行process

         2-1. 正确的 pending 实现：

               bool my_pending(void *ctx) 
                  return work_ready;   // 只读，不改状态

               ---

               void my_process(void *ctx) 
                   if (work_ready)    
                       work_ready = false;   // ★ 在 process 里清标志，不在 pending 里清 ★
                       // 干活...

         2-2. main_loop_only = true 的理解
               打个比喻： 大家依次进屋换衣服。 有两个人是小偷，可能偷衣服，必须让它们排队等候，等别人出来后才让它们进去换衣服
